leetui is the LeetCode side of the desk. Editing happens wherever you already work — nvim in the next tmux pane, a VS Code terminal — so every problem folder says exactly where its file is. Saving re-runs the tests on its own.

Only the marked region is submitted
Everything above it is imports and driver types LeetCode supplies itself and would reject as duplicates.
Test cases are a plain text file
Seeded from the examples, hand-editable, and never overwritten once you add your own.
A local mismatch never claims to be the judge
LeetCode's metadata cannot express in-place mutation or unordered answers, so leetui says so and points at the judge.
Repository main ┊ 3 ahead

Make your workspace a git repository and an accepted verdict commits itself — solution, statement, test cases, notes — with a subject you would have written: 

solve(0146): lru cache — go, 58ms, beats 91.2%
No co-author trailer, no session link
You wrote it. A solutions repo is something people show other people.
Pushing is never automatic
It lives in one screen, behind a confirmation that names the remote's URL — not “origin”.
Only the files it was asked about
Work you staged in another pane is never swept into a commit.
leetui never runs git init for you
A stray .git in a directory you did not mean to version is a real annoyance. It prints the two commands instead.
Install

One static binary, Go 1.24 or newer. Sign in from inside the app by pasting your session cookies — they go to the OS keychain, never to disk, and are never printed.

$ go install github.com/Nano-AI/leetui/cmd/leetui@latest
